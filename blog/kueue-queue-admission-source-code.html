  • 一、从一个最小例子开始
  • 二、核心概念
    • 1. Workload：调度的原子单位
    • 2. LocalQueue：命名空间级的入口
    • 3. ClusterQueue：持有配额的地方
    • 4. ResourceFlavor：节点的"型号"
    • 5. Cohort：跨 ClusterQueue 的配额共享与层级边界
      • 隐式 Cohort：只写同一个名字即可共享
      • 显式 Cohort：用 API 对象描述共享池本身
      • 层级 Cohort 把组织边界放进 quota tree
      • Cohort 改变的不只是可用配额
    • 6. 关键条件：QuotaReserved 与 Admitted
  • 三、Workload 如何进入队列
    • 1. 入队：AddOrUpdateWorkload
    • 2. 出队：Heads 弹出各 CQ 队首
    • 3. 暂不可准入的 Workload 去哪了
      • 从 active heap 到 inadmissibleWorkloads
      • 重新尝试由相关事件触发
      • 移回 active heap 前还会检查条件
      • popCycle 防止错过调度期间的资源变化
      • backoff 是另一条定时重入路径
  • 四、调度器如何准入
    • 1. 取队首与快照
    • 2. 预筛与 flavor 分配：nominate
    • 3. 真正写入准入：admit
    • 4. AdmissionCheck：配额预留不等于放行
    • 5. Preempt：先选择目标，再等待资源真正释放
      • 抢占按 (ResourceFlavor, ResourceName) 核算
      • 只有占用所缺 quota key 的 Workload 才能成为候选
      • 同一个 quota key 只是必要条件
      • FlavorFungibility 是改选 flavor，不是跨 flavor 抢占
      • Kueue 会组合多个 victim 并重新模拟适配
      • 发出抢占不等于立即拿到配额
    • 6. Fair Sharing：公平发生在两个不同层次
  • 五、资源分配——Cache 的配额账本
    • 1. ClusterQueue 的账本结构
    • 2. 记账：addUsage 如何向上冒泡
    • 3. 保底、借用、出借三者的关系
    • 4. 一个具体数字例子
  • 六、准入如何变成"放行"
    • 1. 调度器只管"账"，不管"跑"
    • 2. jobframework 的 startJob
    • 3. Workload 未准入时，将 Job 恢复为 suspend=true
    • 4. WaitForPodsReady：已经放行，但整组 Pod 没跑起来
      • 它和 gang scheduling 的关系
  • 七、资源回收——Workload 完成后的释放
    • 1. 正常完成：Finished → 账本释放
