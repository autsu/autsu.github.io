  • 先把四层边界分开
  • 用户消息进入模型之前
    • 用户 prompt 只是有效上下文的一部分
    • system prompt 规定运行方式，不等于知识库
    • user prompt 说明当前意图
    • AGENTS.md 是运行时加载的项目规则
    • 工具定义不是工具执行
  • 从文字到 token，再到模型请求
    • 编排器先收集环境事实
    • tokenizer 把消息变成离散 token
    • 请求通过网关到达推理服务
  • Prefill、Decode 与 KV Cache
    • Prefill 一次处理整个输入上下文
    • Decode 每次只新增一个位置
    • KV cache 的显存代价
    • 推理调度器会管理 KV block
  • Prompt Cache 与 KV Cache 不是一回事
    • Prefix cache 复用的是 token 前缀
    • 服务商 prompt caching 可能有显式 breakpoint
  • PD 分离：把 Prefill 和 Decode 放到不同资源池
  • 模型的“推理”具体是什么
  • Function Tool 的完整闭环
    • 1. 模型只生成调用请求
    • 2. Runtime 做权限和参数检查
    • 3. 工具进程在模型之外运行
    • 4. tool result 会触发新的模型请求
  • Agent Loop 如何把一次任务跑完
    • 贯穿例子的实际调用序列
      • 读取规则和目录
      • 读取相关代码
      • 用测试或类型检查获取证据
      • 生成补丁
      • 增加并运行回归测试
      • 完成并汇总
  • 上下文会如何增长、压缩和恢复
    • 每一轮逻辑上都要看到历史
    • 工具输出会挤占上下文
    • Compaction 不是 KV cache eviction
    • 文件修改是外部状态，不是对话文本
  • 结束条件不是只有“模型说完了”
  • 一次任务的延迟从哪里来
  • 工具、上下文和安全边界
    • 工具结果是数据，不应自动升级为指令
    • 路径、命令和权限必须在执行器中检查
    • 用户的未提交修改需要被保护
